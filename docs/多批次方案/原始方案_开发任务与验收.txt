接手任务清单（待开发项不是已完成）
前置：先读用户确认需求与代码状态。以下是建议实施顺序，接手者先给用户看方案，确认后再开发。
保护：原业务表、旧结果、人工记录和旧 API 兼容，不覆盖现有数据库；测试使用临时数据库和假模型。

P0-01 数据导入与冻结
入口：/api/upload 及前端选列区。
新增：最终 key/英文版本确认、row_uid、源哈希、列映射预览、空英文/冲突/非法 JSON 阻断清单、只读源快照。
验收：导入/排序/拆批/回填后源值和行数一致；缺英文不调用 API；相同 key 不同文案不会悄悄覆盖。
回归用例：旧表双 id 列；同 key 多场景；新补翻四语列顺序不同；长 JSON；纯链接带签名参数。

P0-02 项目和业务批次管理
新增：Project/Batch/BatchLocale 关联、行清单、批次状态和跨语种总览，操作前有范围预览。
保留：generateDraftWindow/arbitrateWindow 及现有 A/B 独立/C 改写。
验收：一个业务批可拆多个模型请求；批次之间不丢行、不串语种；同一 key 原文不同不可错误缓存。

P0-03 版本与状态正确性
新增：项目/批次不可变配置版本、显式失效处理、统计来自实际目标单元格。
修复关注点：目前每窗口读配置；补翻跳过长文本后可能 completed；已有结果依赖 rowIndex。
验收：在运行中改术语不混同批版本；长文本缺译仍可见；已拒绝/缺失/待复核不会显示“验收完成”。

P0-04 安全的去重与稳定映射
禁止直接复用旧 GET /api/dedup?apply=1 对已翻任务删行。
新增：精确/规范化策略显式选择、冲突预览、用户确认、稳定结果关联、可恢复的操作记录。
验收：本轮精确 key 首条去重能复现 10,580 → 10,496；不会将大小写/标点不同的 key 默认合并。
同一决定仅应用于所确认数据集，旧 18,498 表同 key 多文案仍按记录 ID 追踪。

P0-05 上线与迁移安全
新增：可配置 PORT、鉴权、访问控制、持久化数据库/文件路径、写入一致性或单实例约束。
配置 GET 当前已掩码，不应把这项误列为“首次待加”；仍需保护修改/翻译/数据接口。
验收：无权限不能读取业务数据或触发付费操作；备份可恢复；迁移不覆盖线上数据。

P1-01 试译验收门禁和母语审核
新增：试译样本清单、语种审核负责人、问题类型和放行记录，未批准不得跑生产。
验收：C 高分/AI 复核不能冒充母语人工批准；硬错误阻断；敏感项可强制全审（建议策略，待用户确认）。

P1-02 持久化队列、幂等重试、预算
新增：逐行/语种 checkpoint、重启恢复、暂停/取消、版本化幂等键、usage/费用账本与预算硬停止。
验收：模拟 429/超时/响应乱序/重复 ID/截断/重启，只补失效条目且不覆盖人工结果；未知模型价格标未知。
配置 API Key 的轮换不应泄露到日志/快照；严格 A/B/C 模式缺任一模型先阻断，不用免费兜底冒充完成。

P1-03 术语和语言资源维护
41 候选逐项审定，172 首版锁定词抽检，保留来源和批准状态。
新 GitHub 摘录属于参考，不能整份直接强制导入（其中源键为中文，当前术语匹配基准为英文）。
复核韩语数字/单位规则的适用范围，台湾“帳號停權”等产品术语与摘录“封號”的冲突，马来语风格与语境。
验收：DNT 不命中单词子串；繁中不误回落简中/香港列；候选不参与硬校验；地区和批准历史可追溯。

P1-04 跨批导出和覆盖检查
新增：全项目源版本到结果的完整性对账、三语状态矩阵、失败/待复核清单、合并导出。
验收：修改批次顺序、重试、部分语言通过均不导致错行；正式导出不静默混入失败原文或未批准覆盖。

建议接口（仅设计，不存在于当前代码）
POST /api/projects：登记已确认源版本，不立即翻译。
POST /api/projects/:id/batches/preview：只读预览拆批。
POST /api/projects/:id/batches：用户确认后保存批次。
POST /api/batches/:id/approve /run /pause /retry：分别授权与执行，幂等。
GET /api/projects/:id/coverage：按 row_uid/locale 汇总完整性。
GET /api/projects/:id/export：只导出指定版本/批准范围。
接口名是建议，不要拿它们做现有服务调用。

交付标准
每完成一项提供：实际文件差异、迁移步骤、假模型回归结果、已知限制。
不得仅“网页能打开”或“48项旧测试通过”就宣布批次功能完成。
首次真实试译和付费预算需用户批准；不将“接手开发”理解为自动启动生产。
