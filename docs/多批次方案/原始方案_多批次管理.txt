二、准备阶段（首先执行，不调用模型）
1. 用户确认最终 key 集和可信英文版本。按 key 与必要的平台/场景辅助字段做匹配候选；一对多、缺失、英文冲突全部列为待确认。
2. 保留原始文件和行号；为本次项目分配不可随排序变化的 row_uid。不要用可变 rowIndex 作为跨批唯一身份。
3. 规范字段：row_uid、key、source_en、平台/type、module、usage、context、max_length、参考语列、既有目标语列。
4. 映射导入列时保留原列名称、序号与值，重复表头如旧表 record_id 与 id-ID 明确区分。
5. 预检：空英文、重复/冲突 key、非法 JSON、纯链接、纯 DNT、长文本、格式标记、敏感内容、停用候选。
6. 空英文/冲突/非法源 JSON 阻断，不以其他语言自动替代英文。停用标记仅候选，用户确认后才移出范围。
7. 纯链接按现有规则零模型回填；纯 DNT 整格零模型回填应先补实现和测试，未实现前不要虚报节省。
8. 172 条锁定、41 条候选和 DNT 分开审。候选未确认不得转成强制词；语言规则和强制词冲突先审。

三、试译阶段（须单独取得用户执行及费用批准）
建议选择 100 条代表性 key，而非直接取前 100 行；覆盖功能/关系/语音房/经济、按钮、长句、占位符、JSON、敏感文案。
同一批代表 key 在三个语种分别走 A 独立、B 独立、C 终审改写、程序硬校验、分流和复核。
100 key × 3 语种是 300 个目标单元格，不是 300 次 API 调用；A/B/C、重试、缓存和批量合并会改变实际调用数和 token。
记录实际 usage、成本、失败率、人工改动原因和语言错误类型。没有服务商 usage 时标估算，不能当实际结算。
验收建议：占位符/HTML/JSON/URL/DNT 硬错误全部清零；支付、隐私、封禁、未成年相关文案全部由指定人员核对；其余语种准确性/自然度由母语审核抽检。
具体抽检比例、可接受错误率与预算上限需用户确认。不可用 C 高分替代人工母语验收。
不通过：修改术语/规则，形成新版本，只重跑受影响样本。通过后才批准生产。

四、生产拆批（建议参数，可配置）
按真实功能模块/语境分组；type 的“客户端/服务端/H5”只是平台，不是完整功能模块。
建议普通短文案业务批最多 500 行，JSON/长文本最多 100 行，高风险独立复核批，可先采用最多 250 行。
大 JSON 不能任意截断，后续若拆字符串值，必须保留 JSON path 并支持无损重组及结构校验。
每个业务批固定 row_uid 清单，三个目标语分别记录进度，不因排序或重试重编号。
一个业务批内部仍用现有模型层小批请求/窗口；“500 行业务批”不等于一次给模型发送 500 条。
不得因英文相同就全局复用：先验证 key/场景/地区/术语版本，冲突转人工确认。

五、任务模型（建议，待开发）
Project：project_id、名称、源表版本/哈希、目标语种、预算、负责人、审批状态。
SourceRow：row_uid、原文件/原行、key、source_en、source_hash、场景、引用列、状态。
Batch：batch_id、project_id、不可变 row_uid 列表、处理类别、配置快照ID、状态、创建/审批记录。
BatchLocale：batch_id + locale 的任务、预计/实际费用、完成/失败/待复核数量。
ResultAttempt：row_uid + locale + source_hash + config_version + attempt 的 A/B/C、最终译文、校验、分流、来源、usage。
Snapshot：术语/DNT/知识库/Prompt/模型参数/地区规则/源版本。不要把明文 API Key 放进可导出快照。
Review：记录目标结果版本和 reviewer 类型（human/AI），不能覆盖成同一种“已人工确认”。

六、执行与恢复（待开发，不替换 A/B/C）
批次状态建议：draft → ready → approved → running → needs_review → accepted；另有 failed/paused/cancelled。
状态必须由目标单元格实际完成情况聚合，区分“模型输出已生成”和“正式验收完成”。
重试只处理失败/缺失/明确失效的 row_uid+locale，幂等落库，成功译文不重复扣费。
进程重启后需要持久化检查点和队列恢复，不能仅信任内存 Set/Promise。
配置变动只进入新版本；受影响任务显式作废或重建，不让同批前后偷偷混版本。
预算、速率限制、超时及连续失败触发暂停；恢复需明确确认，避免余额充足就自动启动。

七、交付与验收
按稳定 row_uid/必要的原 key 映射回最终母表，保留原顺序和已有语言，不按跨批行号拼接。
核对批准源范围的 key 数、重复数、每语种完成/缺失/拒绝/待复核数、硬错误数、规则跳过数量。
导出区分 auto、待运营抽查、待人工、人工确认、AI复核。含抽查的导出不叫“全部审核通过”。
重组 JSON、占位符等再跑一次检查；归档源版本、配置版本、结果版本和最终审核记录。
新三语正式执行仍以用户确认和验收为前提，本包没有新三语正式译文成品。
